# 潛水艇出航 GDD(Unity demo)

作者:Visy Lockhart · 最後更新:2026-10-06 · 版本:最終版(對應 repo 目前的實作)

> 本文件描述的是**已實作**的內容。原始企劃中沒做的項目列在「範圍」的「選配(未實作)」與「不做」,不混在規則裡。

## 概述
**潛水艇出航**是單人放置型小遊戲:玩家管理 1–4 艘潛水艇,派它們出航、等待返航、收穫資源,再用資源升級或解鎖下一艘。機制靈感來自 FFXIV 等遊戲常見的潛水艇玩法,但是**原創設計,不使用任何官方素材**。

- 引擎與語言:Unity 6.5(6000.5.1f1,Universal 2D 範本)、C#
- 介面:Unity UI(UGUI)+ TextMeshPro,文字為英文
- 平台:Windows 桌機
- 目標:3 天內完成可玩的完整流程,不追求美術
- 用途:個人學習 Unity 的作品,附本份 GDD

## 核心循環
玩家的決策只有兩件事:**選哪條航線**、**資源花在哪裡**(升級哪艘、升哪一項,或存錢解鎖下一艘)。

1. 在港口選一艘待命(Idle)的潛水艇,按出航
2. 在航線選擇視窗選近海、深海或遠洋(時間與收穫不同),也可以取消
3. 出航後卡片顯示倒數;倒數期間可以關掉遊戲
4. 返航後卡片變成可收穫,按下後跳出結算視窗,顯示獲得的金幣與材料
5. 用金幣與材料升級潛艇,或用金幣解鎖下一艘,再派出去

**目標:** 解鎖全部 4 艘並把每艘的兩項升級都升到 Lv5(畫面上顯示進度 `Lv 目前/40`)。達成時跳一次完成視窗,顯示從開新遊戲到完成的實際時間;之後可以繼續玩,或到設定重設存檔重新挑戰。

## 規則與數值

### 航線
數值存在 ScriptableObject(`Assets/_Project/Data/Routes/` 的 `NearSea`、`DeepSea`、`FarSea` 三個 asset),調整不必改程式。

| 航線 | 遊戲內時間 | 60x 下實際時間 | 金幣 | 材料 | 定位 |
|---|---|---|---|---|---|
| Near Sea(近海) | 10 分鐘 | 10 秒 | 50–80 | 0–1 | 新手航線,頻繁操作 |
| Deep Sea(深海) | 60 分鐘 | 1 分鐘 | 300–450 | 1–3 | 中程 |
| Far Sea(遠洋) | 6 小時 | 6 分鐘 | 2000–3000 | 3–6 | 長程,材料主要來源,適合放置 |

- 金幣與材料各自在範圍內均勻隨機(含上下限)。

### 時間加速
- 倍率三選一:`1x`(真實時間)、`60x`(預設,真實 1 秒 = 遊戲 1 分鐘)、`600x`(快速體驗與展示用)。
- 實際航程 = 遊戲內時間 ÷ 倍率 × 航速倍率(見升級)。
- **返航時間在出航當下就固定**,之後改倍率或升級航速都不影響已經出海的潛艇。
- 倍率存進存檔;設定頁會顯示目前倍率下最長航線的實際時間。
- 倍率越高進度越快,所以三個選項不是平衡的玩法選擇:60x 是設計的遊玩節奏,1x 給想真正放置的人,600x 讓試玩或展示時幾分鐘內就能看完整個流程。

### 升級
每艘潛艇各自有載貨量與航速兩項升級,都從 Lv1 起,最高 Lv5。

| 目前等級 → 下一級 | 金幣 | 材料 |
|---|---|---|
| Lv1 → Lv2 | 100 | 1 |
| Lv2 → Lv3 | 400 | 2 |
| Lv3 → Lv4 | 900 | 3 |
| Lv4 → Lv5 | 1600 | 4 |

- 成本公式:金幣 = 100 × 目前等級²,材料 = 目前等級。一項升滿共 3000 金幣 + 10 個材料。
- **載貨量:** 收穫 × (1 + 0.2 × (等級 − 1)),金幣與材料都套用,四捨五入(0.5 進位)。Lv5 為 1.8 倍。
- **航速:** 航程 × 0.9^(等級 − 1),乘法疊加,不會歸零。Lv5 約為原本的 66%。只影響之後出航的航程。
- 材料只用在升級,讓深海與遠洋航線有存在價值。

### 目標與完成
- 進度 = 已解鎖潛艇的載貨量等級 + 航速等級加總,未解鎖的欄位算 0;滿分 4 艘 × 2 項 × Lv5 = 40。開新遊戲時為 2/40。
- 最後一次升級讓進度達到 40 時,記錄完成時間並跳出完成視窗(只跳一次)。完成時間 = 完成時刻 − 開新遊戲時刻(真實時間,受倍率影響)。
- 開始與完成時間都存進存檔;重設存檔會重新計時。

### 解鎖
- 第 1 艘一開始就有。第 2、3、4 艘分別花 500、1500、4000 金幣解鎖,**必須依序**(先解鎖前一艘)。
- 新解鎖的潛艇從 Lv1 開始。

### 計時與離線補算
- 潛艇只存「出航時間戳」與「返航時間戳」(UTC),狀態每次由現在時間推算:沒有返航時間 = 待命;現在 < 返航時間 = 航行中;否則 = 可收穫。
- 不累加 `Time.deltaTime`,所以暫停、關閉遊戲再開,狀態都正確,離線補算不需要額外邏輯。
- 返航後不會自動收穫,潛艇停在可收穫狀態直到玩家按下。

### 存檔
- 位置:`Application.persistentDataPath/save.json`(Windows 為 `%USERPROFILE%\AppData\LocalLow\<Company Name>\<Product Name>\`),格式為 `JsonUtility` 輸出的 JSON。
- 內容:存檔版本、金幣、材料、時間倍率、開始/完成時間、每艘已解鎖潛艇的兩項等級與航程(航線 id、出航/返航時間戳)。
- 時機:出航、收穫、解鎖、升級、改倍率之後立即存;遊戲暫停或關閉時也存。
- 寫入時先寫暫存檔再替換,避免寫到一半當掉毀損舊檔。
- 讀不到的存檔備份成 `save.json.bak`,並開新遊戲。
- 讀檔時數值會被修正而不是拒絕:負數歸 0、等級夾在 1–5、倍率不合法改回 60x、航線已不存在的航程視為待命。
- 設定頁的重設存檔要按兩次確認。

## 介面
單一場景 `Harbor`,5 個主要畫面加完成視窗,對話框以全畫面遮罩蓋在主畫面上。

1. **主畫面(港口):** 上方顯示金幣與材料與設定按鈕;中間 4 張潛艇卡片,顯示名稱、兩項等級、狀態、倒數、主按鈕(出航/收穫)與升級按鈕;兩項升級都滿級時升級按鈕顯示 MAX 並停用。未解鎖的卡片顯示解鎖價格,只有下一艘可以按,金幣不足時按鈕停用。
2. **航線選擇:** 點待命潛艇的出航後跳出,列出 3 條航線的遊戲內時間、以及這艘潛艇在目前倍率下的實際等待時間與收穫範圍(已套用它的航速與載貨量等級),可取消。
3. **收穫結算:** 點可收穫的潛艇後跳出,顯示潛艇名稱、航線與獲得的金幣、材料。
4. **升級商店:** 點卡片的升級按鈕後跳出,顯示這艘潛艇兩項升級的目前等級、效果與下一級價格;滿級或資源不足時按鈕停用。
5. **設定:** 時間倍率三選一、目前倍率下最長航程、兩段式重設存檔。
6. **完成視窗:** 艦隊目標達成時跳出一次,顯示完成時間與「繼續玩或重設」的提示。主畫面上方的目標進度改為 `Fleet complete!`。

## 技術設計

**原則:遊戲規則寫成純 C# 類別,不繼承 `MonoBehaviour`、不引用 `UnityEngine`;介面層只負責顯示和轉送輸入。** 規則因此能用 EditMode 測試直接驗證,分層方式也對應後端常見的 domain / infrastructure / presentation。

### 組件(Assembly Definition)

| asmdef | 位置 | 職責 | 相依 |
|---|---|---|---|
| `SubmarineVoyage.Core` | `Scripts/Core` | 遊戲規則,設定 `noEngineReferences` | 無 |
| `SubmarineVoyage.Data` | `Scripts/Data` | ScriptableObject 與檔案存取 | Core、UnityEngine |
| `SubmarineVoyage.UI` | `Scripts/UI` | `MonoBehaviour` 畫面 | Core、Data、UGUI、TextMeshPro |
| `SubmarineVoyage.Core.Tests` | `Tests/EditMode` | NUnit EditMode 測試 | Core |

### 主要類別

| 類別 | 層 | 責任 |
|---|---|---|
| `Submarine` | Core | 一艘潛艇:由返航時間戳推算狀態(待命 → 航行中 → 可收穫)、出航、收穫、升級 |
| `Fleet` | Core | 4 個潛艇欄位、解鎖價格與依序解鎖、目標進度(等級加總) |
| `Wallet` | Core | 金幣與材料的增減與足夠檢查 |
| `Route` / `Reward` | Core | 航線資料(與 Unity 無關)、一次收穫的結果 |
| `UpgradeRules` | Core | 升級等級上限、成本與倍率公式,集中在一處方便調整 |
| `GameState` / `TimeScaleOptions` | Core | 要存檔的全部狀態(錢包、艦隊、倍率、開始/完成時間)、目標完成判定,與允許的倍率 |
| `SaveData` / `SaveMapper` | Core | 可序列化的存檔快照,以及與 `GameState` 互轉(含讀檔修正) |
| `IClock` / `IRandomSource` | Core | 時間與亂數的介面,測試時可替換成固定值 |
| `RouteDefinition` | Data | 航線的 ScriptableObject,轉成 Core 的 `Route` |
| `JsonSaveStore` | Data | 讀寫 `save.json`(暫存檔替換、壞檔備份) |
| `HarborController` | UI | 場景入口:建立/載入 `GameState`,接收各畫面的事件、呼叫 Core、存檔、更新畫面 |
| `SubmarineCardView`、`RouteSelectionView`、`RouteButtonView`、`RewardView`、`CompletionView`、`UpgradeShopView`、`UpgradeRowView`、`SettingsView` | UI | 各畫面:只顯示資料並以 C# event 把按鈕輸入轉送給 `HarborController` |

原始企劃中的 `VoyageSystem`(出航、判斷返航、結算)沒有獨立成類別:這些行為都只與單一潛艇有關,直接放在 `Submarine` 比較單純。`SaveSystem` 拆成 Core 的 `SaveMapper`(純資料轉換,可測試)與 Data 的 `JsonSaveStore`(實際檔案 I/O)。

### 測試
- EditMode 測試 32 個(Unity Test Runner),涵蓋潛艇狀態與計時、收穫與載貨量倍率、升級成本與上限、依序解鎖、目標進度與完成判定、存檔來回轉換與讀檔修正。
- 時間與亂數透過 `IClock`、`IRandomSource` 注入,測試不需要等待真實時間。

## 試玩調整紀錄
第 3 天由作者以 600x 從新遊戲試玩到四艘全部升滿。

| 發現的問題 | 調整 |
|---|---|
| 航線選擇視窗的等待時間與收穫範圍沒有套用潛艇的升級,升級後顯示與實際不符 | 改為依該艘潛艇計算(航速、載貨量) |
| 已升滿的潛艇仍顯示可按的升級按鈕 | 兩項都滿級時顯示 MAX 並停用 |
| 升滿後沒有目標,也沒有完成提示,只剩重複出航與收穫 | 加入艦隊目標進度與一次性的完成視窗 |
| 600x 明顯最有效率 | 維持三種倍率,在 GDD 說明各倍率的用途 |

數值(航線收穫、升級成本、解鎖價格)試玩後維持初始值。
